Binary Search

01Мотивация

Базовая идея: монотонность вместо перебора

Binary search применяется к пространству, где есть монотонное свойство — то есть можно провести границу, до которой условие ложно, а после которой истинно (или наоборот). Классический случай — отсортированный массив, где значение монотонно растёт слева направо. Но это лишь частный случай: монотонным может быть не сам массив, а предикат над произвольным пространством ответов — эта идея разворачивается в разделе 04 и оказывается важнее самого «поиска в массиве».

На каждом шаге проверяется средний элемент диапазона, и в зависимости от результата отбрасывается ровно половина пространства поиска. Каждая проверка вдвое сокращает то, что осталось проверить — отсюда $O(\log n)$ вместо $O(n)$ линейного перебора.

!

Требование: пространство поиска должно быть монотонным относительно условия, которое ты проверяешь. Если это не так — binary search молча даст неверный результат, даже если он «запустится» и что-то вернёт. Монотонность нужно доказать себе до того, как садиться писать код, а не понадеяться, что «вроде работает».

02Шаблон №1

Базовый шаблон: поиск точного значения

def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = left + (right - left) // 2   # так, а не (left+right)//2 — привычка от переполнения в других языках,
                                            # в Python не критично, но так принято
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1  # не найдено

Ключевые моменты

while left <= rightИменно <=, а не < — иначе пропустишь случай, когда для проверки остался последний элемент диапазона (left == right).
left = mid + 1 / right = mid - 1Границу обязательно нужно сдвигать мимо mid. mid уже проверен и точно не подходит — если оставить его в новом диапазоне (например, написать left = mid), при определённых значениях диапазон перестанет сужаться и получится бесконечный цикл.

03Шаблон №2

Шаблон «найти границу» (lower_bound / upper_bound)

Этот шаблон на практике встречается чаще, чем поиск точного значения — особенно когда в массиве есть дубликаты или нужно найти «первый элемент, удовлетворяющий условию».

def lower_bound(arr, target):
    # первый индекс, где arr[i] >= target
    left, right = 0, len(arr)
    while left < right:
        mid = left + (right - left) // 2
        if arr[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left

Отличия от базового шаблона

right = len(arr)вместо len(arr) - 1 — правая граница невключительная.
while left < rightвместо left <= right.
Нет отдельной ветки ==просто сужаем диапазон до одной точки — сравниваем только < vs «не <».
В конце left == rightэто и есть искомая граница; она может быть равна len(arr), если подходящего элемента нет вообще — это обязательно нужно проверять в вызывающем коде.

Для upper_bound (первый индекс, где arr[i] > target) меняется только условие внутри цикла: if arr[mid] <= target: left = mid + 1.

Самый универсальный шаблон

Этот шаблон не ломается на дубликатах и легко адаптируется под любое монотонное условие — не только сравнение с числом, но и произвольный предикат. Стоит выучить именно его как основной, а вариант с отдельной веткой == использовать только для совсем простых задач на точное совпадение.

04Ключевая идея темы

Binary search on answer (параметрический поиск)

Самая важная концепция для medium/hard-задач на эту тему. Суть: ты ищешь не индекс в массиве, а оптимальное значение параметра $X$, при котором выполняется некоторое условие feasible(X) — и это условие монотонно по $X$: если оно выполняется для $X$, то выполняется и для всех $X'$ по одну сторону от $X$.

def find_min_feasible(lo, hi, feasible):
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if feasible(mid):
            hi = mid       # mid подходит, но, может, есть меньше — не отбрасываем mid
        else:
            lo = mid + 1   # mid точно не подходит
    return lo

Как распознать, что нужен этот подход

«минимальное/максимальное X, такое что...» «найти наименьшее k, чтобы...» прямой перебор X дал бы верный, но слишком медленный ответ если X подходит — любое X' по ту же сторону тоже подходит

Пример мышления: Koko Eating Bananas

Задача: «с какой минимальной скоростью нужно есть бананы, чтобы успеть съесть все кучи за $h$ часов». Прямой перебор скорости от 1 до $\max(\text{piles})$ с проверкой «успеет ли за это время» даёт $O(n \cdot \max(\text{piles}))$ — слишком медленно. Но здесь есть монотонность: если скорость $k$ достаточна, то и любая скорость больше $k$ тоже достаточна. Значит можно применить binary search — не по массиву куч, а по пространству возможных скоростей.

!

Это концептуально сложнее обычного binary search, потому что здесь нет отсортированного массива — функцию feasible(X) нужно придумать самому. Вся сложность задачи сводится к двум вещам: (1) понять, что здесь вообще применим binary search, и (2) правильно и достаточно быстро реализовать feasible(X).

05Нарушенная монотонность

Binary search в повёрнутом (rotated) массиве

Массив был отсортирован, а затем «повёрнут» — циклически сдвинут. Целиком он уже не монотонен, но здесь есть более тонкое свойство, которое и нужно использовать: в любой момент одна из двух половин относительно mid точно отсортирована.

Алгоритм: определи, какая половина отсортирована (сравнив arr[left] и arr[mid]):

  • если arr[left] <= arr[mid] — отсортирована левая половина;
  • иначе — отсортирована правая половина.

Дальше, зная, какая половина точно отсортирована, легко проверить, попадает ли target в её диапазон значений (обычным сравнением с границами). Если попадает — искать в этой половине как в обычном отсортированном массиве; если нет — искать в другой половине (которая, в свою очередь, при следующем шаге снова разделится на «точно отсортированную» и «остальную»).

06Два измерения

Binary search в 2D

Матрица отсортирована по строкам глобально
первый элемент каждой строки больше последнего элемента предыдущей		 Её можно рассматривать как один «виртуальный» отсортированный массив длины $m \times n$ и применять обычный binary search, пересчитывая индекс: row = mid // cols, col = mid % cols.
Матрица отсортирована по строкам и столбцам независимо
но не глобально		 Другой приём — старт из угла (например, верхний правый) и движение по строке/столбцу в зависимости от сравнения с target. Формально это не совсем binary search, а staircase search, но эти задачи часто идут в одной теме.

07Что чаще всего идёт не так

Частые ошибки

Бесконечный циклНеправильный сдвиг границ — написать left = mid вместо left = mid + 1, когда mid уже проверен и точно не подходит. Диапазон перестаёт сужаться.
Смешение шаблоновПерепутать шаблон «точный поиск» (right = len-1, left <= right) с шаблоном «поиск границы» (right = len, left < right) — брать половину условий из одного, половину из другого.
Применение там, где нет монотонностиСначала нужно доказать себе, что свойство/предикат монотонны, и только потом писать код — иначе binary search молча вернёт неверный ответ.
Забытая сложность feasible()Для binary search on answer: если сама функция feasible(X) стоит $O(n)$, а внешний binary search делает $O(\log(\text{range}))$ итераций, итоговая сложность — $O(n \log(\text{range}))$. Это нужно явно понимать и проговаривать на собеседовании, а не молчаливо считать весь алгоритм «логарифмическим».

  1. 704, 35 — закрепить базовый шаблон и lower_bound на самом простом уровне.
  2. 278, 69, 367 — первое знакомство с идеей «binary search на предикате», ещё без сложной feasible().
  3. 34 — совместить lower_bound и upper_bound в одной задаче, это часто спрашивают на medium.
  4. 33, 153 — rotated array, понять идею «одна половина всегда отсортирована».
  5. 875 — первая полноценная binary search on answer задача. Не переходить дальше, пока не разобрана досконально — это самая частая идея на medium-собеседованиях.
  6. 1283, 1011, 1482 — закрепление параметрического поиска на вариациях.
  7. 162, 74, 240 — если осталось время, добить оставшиеся классические варианты (peak element, 2D).
  8. 1552, 287, 378 — более нестандартные применения темы.
  9. 410, 4 (при наличии времени перед собеседованием) — hard-уровень: посмотреть, но не заморачиваться, если не идёт с первого раза.

10Итоги

Самое важное

Разобрано:

  • Базовая идея: монотонность условия, а не обязательно сортировка массива — $O(\log n)$ за счёт отбрасывания половины пространства поиска на каждом шаге
  • Базовый шаблон точного поиска и его две ключевые ловушки (<= в условии цикла, сдвиг мимо mid)
  • Шаблон lower_bound/upper_bound — более универсальный, не ломается на дубликатах
  • Binary search on answer: поиск оптимального параметра через монотонный предикат feasible(X), а не индекса в массиве
  • Повёрнутый массив: в любой момент одна из половин относительно mid точно отсортирована
  • 2D: матрица как виртуальный массив (глобальная сортировка) или staircase search (независимая сортировка по строкам/столбцам)
  • Частые ошибки: бесконечный цикл, смешение шаблонов, применение без доказанной монотонности, забытая сложность feasible()

Что стоит запомнить:

  • Монотонность — это свойство условия/предиката, а не обязательно отсортированности самого массива
  • Шаблон lower_bound стоит выучить как основной — он покрывает почти все практические случаи, включая точный поиск
  • Binary search on answer — самая частая продвинутая идея на medium-собеседованиях: если прямой перебор параметра монотонен по результату, его можно ускорить бинарным поиском
  • Итоговая сложность binary search on answer — это $O(\log(\text{range}))$, умноженное на сложность самой функции feasible(), а не просто «логарифм»
